## Post draft 1: Statistical software and interpretation

A statistical result is only useful if someone can interpret it.

I am a co-author of autopsych, an R Shiny tool described in a 2021 PLOS ONE paper. The collaborative project brings assessment analysis into a guided interface, alongside reports and outputs that users can inspect.

The design question interests me as much as the calculation: how do we make a method accessible while keeping its assumptions visible?

A useful interface can help someone run an analysis. It should also help them understand the limits of the result.

Paper and author contributions: https://doi.org/10.1371/journal.pone.0257682

What helps you judge whether an analytical tool is giving you enough context to use its output?

## Post draft 2: Transformations need an explanation

Transforming a variable should come with an explanation of why.

In our 2018 paper on non-normality, Matthew Courtney and I presented a practical guide using R, with associated software for transforming variables.

The question behind a transformation matters: which assumption are we trying to address, and how will the transformed scale affect interpretation?

For a reproducible analysis, I want the chosen method and its assumptions documented alongside the code.

The paper remains available here: https://doi.org/10.1111/test.12154

The associated normalr package is now archived on CRAN, so this is a historical methods reference rather than a recommendation of maintained software: https://CRAN.R-project.org/package=normalr

## Post draft 3: Think about the design before the analysis

Some analytical problems start before the data are collected.

My doctoral research examined computer-generated designs for two-phase experiments, with applications to multiplex experiments in proteomics.

It is a different setting from banking pricing, but it raises a useful general question: what can the design of the evidence let us learn?

Before choosing an analysis, clarify the comparison, the sources of variation and the assumptions needed to interpret the result.

My thesis record: https://hdl.handle.net/2292/37016

When do you bring a statistician into a project: while framing the question, designing the evidence or analysing the results?
